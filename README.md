# RAG Performance Improvement on HotpotQA

This project aims to improve Retrieval-Augmented Generation (RAG) performance on the HotpotQA dataset. It explores baseline RAG approaches and introduces custom improvements (such as customized rerankers and contextual thresholding) to yield higher quality document retrieval and more accurate answering.

## Project Structure

The project has been refactored for clarity and modularity. The codebase is organized as follows:

```
.
├── src/
│   ├── data/
│   │   ├── buildDB.py                # Constructs FAISS index and metadata for standard documents
│   │   └── build_testset.py          # Script for generating subsets of train/test data or specific metadata structures
│   ├── pipeline/
│   │   ├── rag_baseline.py           # Standard Baseline RAG execution (Retrieval -> Generation)
│   │   └── rag_ours.py               # Proposed RAG method (Two-stage retrieval/reranking with LLM formatting)
│   ├── evaluation/
│   │   ├── rag_evaluation_f1.py      # Computes Exact Match (EM) and F1-score for RAG output
│   │   ├── rag_evaluation_llm.py     # Uses a strong LLM as a Judge (e.g. Llama-3.2-3B) to score accuracy
│   │   ├── recall_evaluate.py        # Evaluates document retrieval recall/precision metrics
│   │   ├── factscount.py             # Counts matching facts in outputs
│   │   └── summarize_generate.py     # Prototype/playground for summarization and answering steps
│   └── training/
│       ├── reranker_train.py         # Trains a custom CrossEncoder reranker
│       └── train_hyperparameter.py   # Hyperparameter search/tuning for reranker training
├── results/                          # Directory containing model outputs and evaluation scores
│   ├── rag_baseline_results.json
│   ├── rag_ours_results.json
│   ├── title_full_results.json
│   └── evaluation_results_title_full.json
└── README.md
```

## Setup and Data Preparation

Before running the pipelines, you need to set up the FAISS indexes and metadata databases.

1. Install the required libraries (e.g., `sentence-transformers`, `faiss-cpu` or `faiss-gpu`, `transformers`, `datasets`).
2. Run the database construction scripts located in `src/data/`:
   ```bash
   python src/data/buildDB.py
   python src/data/build_testset.py
   ```
   *Note: Ensure paths in the scripts (like `~/faiss/`) match your system configuration.*

## Running the Pipelines

### Baseline RAG
Runs standard Retrieval-Augmented Generation leveraging CrossEncoder for reranking and Llama-3.2-1B for generation.
```bash
python src/pipeline/rag_baseline.py
```
Outputs are typically saved to `results/rag_baseline_results.json`.

### Proposed RAG Method (Ours)
Implements a more complex two-stage retrieval (document-level then sentence-level reranking) with thresholding rules and customized models.
```bash
python src/pipeline/rag_ours.py
```
Outputs are typically saved to `results/title_full_results.json`.

## Evaluation

You can evaluate the results generated by the pipelines using either standard metrics (Exact Match / F1) or LLM-as-a-judge (0-10 Accuracy scaling).

### Exact Match & F1
```bash
python src/evaluation/rag_evaluation_f1.py
```

### LLM as a Judge
Uses an LLM (e.g., Llama-3.2-3B-Instruct) to score the accuracy and explain the reasoning.
```bash
python src/evaluation/rag_evaluation_llm.py
```

## Results JSON Structure
The generated results in the `results/` folder typically follow this structure:
```json
[
  {
    "question": "Question text...",
    "ground_truth": "Actual answer...",
    "predicted_answer": "Model's generated answer...",
    "summary": "Model's intermediate summarized context..."
  }
]
```

## Model Fine-tuning
For reproducing our proposed pipeline, you may need to train a custom reranker. The code for this is located in `src/training/`.
```bash
python src/training/reranker_train.py
```
